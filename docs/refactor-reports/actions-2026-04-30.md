## Finding 1: `ActionResult<T>` type redefined in every action file

**Type**: Duplicated type definition
**Appears in**:
- `src/actions/ai.ts` (line 7)
- `src/actions/items.ts` (lines 10–12)
- `src/actions/collections.ts` (lines 15–17)
- `src/actions/settings.ts` (lines 8–10)

**Repeated code** (identical in all four files):
```typescript
type ActionResult<T> =
  | { success: true; data: T }
  | { success: false; error: string };
```

**Proposed extraction**:
- **Extract to**: `src/types/actions.ts` (new file)
- **Name**: `export type ActionResult<T> = { success: true; data: T } | { success: false; error: string }`
- **Rationale**: Single source of truth. If the shape ever changes (e.g., adding an `errorCode` field), it changes in one place. All four action files import from there.
- **Estimated lines saved**: ~8 lines removed + consistent import across the codebase

## Finding 2: Auth session guard repeated in every action function (16 occurrences)

**Type**: Repeated auth boilerplate
**Appears in**:
- `src/actions/items.ts` (lines 18–20, 47–49, 101–103, 112–114, 122–124) — 5 functions
- `src/actions/collections.ts` (lines 54–56, 77–79, 96–98, 109–111) — 4 functions (plus a silent-fail variant at line 30–31)
- `src/actions/ai.ts` (lines 14–16, 94–96, 155–157, 208–210) — 4 functions
- `src/actions/settings.ts` (line 24–25) — 1 function

**Repeated code** (from `items.ts:18–20`, same in 15 other places):
```typescript
const session = await auth();
if (!session?.user?.id) {
  return { success: false, error: 'Unauthorized' };
}
```

**Proposed extraction**:
- **Extract to**: `src/lib/action-utils.ts` (new file)
- **Name**: `requireSession(): Promise<{ id: string } | ActionResult<never>>`
- **Usage pattern**:
```typescript
// Instead of 3 lines every function, just:
const session = await requireSession();
if (!session.success) return session;
const userId = session.data.id;
```
- **Rationale**: 16 occurrences means any change to the auth guard (e.g., adding a suspended-account check) requires touching 5 files. Centralizing reduces drift risk.
- **Estimated lines saved**: ~32 lines across 16 call sites

> **Note**: The variant in `search.ts` (line 27–28) and `getUserCollections` (collections.ts:30–31) that returns an empty value instead of an error result is intentional — do not consolidate those two with the error-returning pattern.

## Finding 3: Zod parse-error extraction repeated in 5 action functions

**Type**: Duplicated error extraction pattern
**Appears in**:
- `src/actions/items.ts` (lines 24–26 in `updateItem`, lines 53–55 in `createItem`)
- `src/actions/collections.ts` (lines 60–62 in `updateCollection`, lines 83–84 in `deleteCollection`, lines 115–116 in `createCollection`)

**Repeated code** (from `items.ts:24–26`, identical in all five):
```typescript
const message = parsed.error.issues.map((e) => e.message).join(', ');
return { success: false, error: message };
```

**Proposed extraction**:
- **Extract to**: `src/lib/action-utils.ts` (same file as Finding 2)
- **Name**: `zodError(result: SafeParseError<unknown>): ActionResult<never>`
```typescript
export function zodError(result: z.SafeParseError<unknown>): ActionResult<never> {
  return { success: false, error: result.error.issues.map((e) => e.message).join(', ') };
}
```
- **Usage at call sites**:
```typescript
const parsed = Schema.safeParse(raw);
if (!parsed.success) return zodError(parsed);
```
- **Rationale**: Collapses 2 lines to 1, and makes the Zod error format a single decision. If the format changes (e.g., switching to the first issue only), it changes in one place.
- **Estimated lines saved**: ~5 lines across 5 call sites

## Finding 4: AI catch block is copy-pasted verbatim 4 times in `ai.ts`

**Type**: Duplicated error handler
**Appears in**:
- `src/actions/ai.ts` (lines 71–84) — `generateAutoTags`
- `src/actions/ai.ts` (lines 127–140) — `explainCode`
- `src/actions/ai.ts` (lines 190–203) — `generateDescription`
- `src/actions/ai.ts` (lines 238–251) — `optimizePrompt`

**Repeated code** (lines 71–84, byte-for-byte identical in all four):
```typescript
} catch (err) {
  const message = err instanceof Error ? err.message : '';

  if (message.includes('insufficient_quota') || message.includes('billing')) {
    return { success: false, error: 'AI service is temporarily unavailable. Please try again later.' };
  }
  if (message.includes('rate_limit')) {
    return { success: false, error: 'AI rate limit reached. Please try again in a moment.' };
  }
  if (message.includes('invalid_api_key') || message.includes('authentication')) {
    return { success: false, error: 'AI service configuration error. Please contact support.' };
  }

  return { success: false, error: 'AI service error. Please try again.' };
}
```

**Proposed extraction**:
- **Extract to**: `src/lib/ai-error.ts` (new file, or fold into the existing `src/lib/openai.ts`)
- **Name**: `handleAIError(err: unknown): ActionResult<never>`
```typescript
export function handleAIError(err: unknown): ActionResult<never> {
  const message = err instanceof Error ? err.message : '';
  if (message.includes('insufficient_quota') || message.includes('billing'))
    return { success: false, error: 'AI service is temporarily unavailable. Please try again later.' };
  if (message.includes('rate_limit'))
    return { success: false, error: 'AI rate limit reached. Please try again in a moment.' };
  if (message.includes('invalid_api_key') || message.includes('authentication'))
    return { success: false, error: 'AI service configuration error. Please contact support.' };
  return { success: false, error: 'AI service error. Please try again.' };
}
```
- **Usage at call sites**:
```typescript
} catch (err) {
  return handleAIError(err);
}
```
- **Rationale**: This is the highest-impact extraction. 52 lines of identical error-handling code collapses to 4 lines across 4 catch blocks. Adding a new OpenAI error class (e.g., `context_length_exceeded`) currently requires editing 4 places.
- **Estimated lines saved**: ~48 lines in `ai.ts` alone

**Highest-impact extraction**: Finding 4 (`handleAIError`) — 48 lines removed from a single file, and the most likely to drift if a new OpenAI error type needs handling.

**Suggested order**:
1. **Finding 4 first** — self-contained to `ai.ts`, easiest to test (all 4 AI actions covered by existing unit tests), highest line reduction.
2. **Finding 1 second** — create `src/types/actions.ts`, update imports in all 4 files. Zero logic change, pure extraction.
3. **Finding 3 third** — create `zodError()` in `src/lib/action-utils.ts`, update 5 call sites. Minimal risk.
4. **Finding 2 last** — `requireSession()` changes the calling pattern more significantly and should be done after the other extractions are committed and tests pass.

**Patterns not worth extracting**:
- The Pro + free-tier limit guard in `createItem` and `createCollection` — the logic differs enough (item limit vs. collection limit, different type checks) that a shared wrapper would need too many parameters.
- The `isPro` check in individual AI functions — the per-feature error message (`'AI auto-tagging requires DevStash Pro.'`, `'AI code explanation requires DevStash Pro.'`) is intentionally distinct per action.
